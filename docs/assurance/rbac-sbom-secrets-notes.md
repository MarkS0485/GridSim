# Access control, supply chain and secrets - assurance notes

Companion to `caf-mapping.md` and `nis-oes-gap-assessment.md`, as at GridSim 1.95.296, against NCSC CAF v4.0 (released 6 August 2025). These notes record, for access control, the software bill of materials, secrets and availability, what is in place today, with the type and test that evidences each, and the few remaining deploying-party actions. Statuses of record are in `caf-mapping.md` section 8. None of this weakens the load-bearing control: the `ForwardInferenceGuard` 169 h data boundary, which is enforced in code and needs no operator to be correct.

## 1. Access control

**In place.** The web host authenticates with a sign-in cookie and a single sign-on consumer (single-use, audience-checked tickets; it never acts as an authority). The production configuration runs replay-only (`GridSim:ReplayOnly`), which leaves the `/api` and `/ws/sim` endpoints unmapped, so a public instance has no solve surface to protect. Concurrent sessions are capped (`GridSim:MaxSessions`). `gridsim serve` binds no network port, and `GridBridgeClient` is an outbound client.

**Built as a primitive, not yet enforced (Partially achieved): role-based access-control gate.** The gate is built and tested (`GridSim.Core.Security`): `OperationRole` (`Viewer`, `Analyst`, `Operator`, `Administrator`), `IdentityContext` (principal id, role, correlation id from the cookie or SSO claims), `RoleGuard.Require(IdentityContext, OperationRole)` throwing `AccessDeniedException`, and an audited overload that writes a `SecurityEventKind.AccessDenied` audit entry for each deny. No hosting surface (endpoint, CLI verb or hosted service) calls it at this release, so nothing is authorised by role and no denial is ever written to an audit log; the manifest records `rbac` as Partially achieved. Evidence: `RoleGuardTests` (the primitive).

The least-privilege bands scope the service when the solve surface is exposed (the web host with replay-only off, or `RealtimeEstimatorHostedService`): a Viewer or Analyst subscribes to estimated-state frames and quality metrics (chi-square, covariance); an Operator additionally starts / stops / seeks the resident estimator and selects the bridge source (`presolved`, `estimated`, `live`, `solves`, `raw`); an Administrator additionally changes configuration (cadence, network model, feeds).

The gate is the mechanism intended for the solve surface when it is exposed; at this release no hosting surface calls it, so it does not authorise `/api` or `/ws/sim` (existing constitutional tests reach the solve surface without a role). The shipped exposure control in production is the replay-only gate (`GridSim:ReplayOnly` leaves `/api` and `/ws/sim` unmapped). Closing the gap means enforcing it in the hosting layer (with the identity the sign-in establishes and the host's audit writer), not in the Core library - Core stays a pure, side-effect-free estimator. The horizon guard is independent of the gate: even an Administrator cannot make the estimator process data newer than the horizon, because the guard consults no role and has no bypass, and it caps what any caller can learn (week-stale reconstruction only) regardless of role.

## 2. Software Bill of Materials (SBOM)

**In place.** The release workflow builds two CycloneDX SBOMs (the CLI and the web host) from the .NET restore graph and attaches them to the GitHub Release next to the artefacts they describe (CAF objective A / NIS supply chain). CI and the release fail on a known-vulnerable direct or transitive package; NuGet audit warnings are build errors; CodeQL scans the C# when run by hand; Dependabot proposes grouped dependency updates monthly; `THIRD-PARTY-NOTICES.md` names every shipped package and its licence (`ThirdPartyNoticesTests`). Every file on the GitHub Release (the CLI archives, the SBOMs and `SHA256SUMS.txt`) gets a signed build-provenance attestation (`gh attestation verify <file> -R <owner>/GridSim`). The Windows CLI binary and the NuGet package are signed when the signing secret is configured, with a self-signed certificate that the release's verify steps trust only by its pinned thumbprint; without the secret the release is unsigned, with a warning. The Linux and macOS archives, `SHA256SUMS.txt` and the container image are not signed.

- The dependency surface is deliberately small: the Core estimator has **no third-party runtime dependencies** beyond the .NET base class library (linear algebra, XML, crypto are all BCL); the web host adds ASP.NET Core; tests add xUnit. A small surface is itself an assurance property.
- Review transitive additions in pull requests.

**In place.** Per-project `packages.lock.json` lock files (`RestorePackagesWithLockFile=true` in `Directory.Build.props`) pin the restore graph; `BuildProvenance` (`GridSim.Core.Diagnostics.SupplyChain`) exposes version, commit, toolchain (the .NET SDK stamped at build time), SBOM hash and build hash at runtime. The release generates the SBOMs first and builds the CLI, the web image and the NuGet package with the SBOM hash injected (`-p:GridSimSbomSha256=<hash>`); each CLI binary must report `release build  yes` and that hash from `gridsim compliance verify`, or the release stops. The build hash is an identity label over those metadata strings, not an integrity proof (it covers no artefact bytes); download integrity comes from the provenance attestation, `SHA256SUMS.txt` and Authenticode. `ComplianceManifest` (a hand-maintained inventory) + `ComplianceAttestation` bind the control inventory to the build identity: the verdict is COMPLIANT only for a release build with every in-scope control recorded Achieved; a local build reports `NOT ATTESTED` and `gridsim compliance verify` exits 1. At this release `rbac`, `distrusted-source` and `resilience` are recorded Partially achieved, so a release build reads `NOT COMPLIANT` (the A4.b secure-SDLC attestation). Evidence: `SupplyChainManifestTests`, `ComplianceAttestationTests`, `WorkflowReleaseGateTests`.

**Deploying-party action.** Running the first tagged release, which publishes the SBOMs and exercises the provenance and signing steps on GitHub; CI runs at the release (every publishing job waits for the full matrix) or by hand, not on every push, a risk-accepted deviation (see `caf-mapping.md` section 4.4).

## 3. Secrets management

The estimator itself holds **no secrets** in its core path - it consumes files and streams of measurements and emits states. Secrets appear only at the edges:

- Feed credentials (a PMU / PDC endpoint, a lake path, a message bus) and the licence key - supplied through environment variables or configuration, never committed.
- The web host's data-protection key ring - encrypted at rest with DPAPI on Windows by default, and with a PKCS#12 certificate elsewhere when `Auth:KeyCertificatePath` is set (without one, Linux stores the keys unencrypted and warns at start-up); a protection setting that cannot be honoured stops start-up.
- Release signing material - held in repository secrets only; the repository holds the public certificate.
- Any operator API auth material - handled by the hosting layer's sign-in.

**In place.** `ISecretStore` (`GridSim.Core.Security`), with `EnvironmentSecretStore`, `DirectorySecretStore`, `CompositeSecretStore` and `NullSecretStore`, is BCL-only (no new third-party dependency); services resolve secrets (for example the key-ring certificate password, through `KeyRingProtection`) through it rather than from plain configuration. `DirectorySecretStore` reads one file per secret (Docker / Compose secrets at `/run/secrets`, a Kubernetes secret volume, systemd `$CREDENTIALS_DIRECTORY`); the web setting `Secrets:Directory` puts it in front of the environment, so the key-ring certificate password need not be in configuration or the environment. No OS-keychain or vault backend ships; a deployer can supply their own `ISecretStore` in code. The licence key is signed, not encrypted (it is inspectable, not a confidential secret), so it needs no store. Evidence: `SecretStoreTests`, `DirectorySecretStoreTests`, `NoSecretInAuditTests`.

Rule: no secret in source, no secret in the audit log (the audit trail records provenance, timestamps, input hashes and verdicts - never credentials), no secret in an exported state. A test enforces the audit rule: `NoSecretInAuditTests`.

## 4. Availability and minimising impact (CAF B5, D1)

**In place.** The resident estimator continues past a failed window by default (`ContinueOnError`) and reports processed / converged / rejected / failed counts; `GridBridgeClient` times out a query after 60 s and fails every pending query when the stream faults; the web host caps sessions; the container health check probes the web host. The chi-square gate and the `FdiaScreen` are the "detect a bad or attacked state before acting on it" controls; the audit trail is the forensic record; the deterministic replay path (`GdaReplayLoop`, and `RealtimeEstimatorEngine` on a recorded window stream) re-derives a past state bit for bit for post-event forensics.

**In place.** `ResilienceOptions` (`GridSim.Core.Net`) carries the resource limits (bridge message cap, in-flight-query cap) and the transport policy, and the web and desktop hosts apply it to every bridge client they create; `GridBridgeClient` refuses an unencrypted `ws://` endpoint unless explicitly allowed (web `GridSim:BridgeAllowUnencrypted=true`, desktop `BridgeAllowUnencrypted`; without it a `ws://` endpoint stops web start-up). `ServiceLevelObjective` + `HealthProbe` (`GridSim.Core.Simulation.Health`) fold the engine's `RealtimeRunSummary` into a `HealthReport`; at the end of a `gridsim serve` run with `--audit-log`, or of the web resident estimator's run with `Audit:LogPath`, an SLO breach is recorded as an `AvailabilityDegraded` security event, which becomes an incident when `--incident-log` / `Audit:IncidentLogPath` is set (the `/health` endpoint itself raises nothing; it answers 503). There is no degraded-mode fallback to a last-good estimate: a failing window is skipped and counted and the resident loop carries on (`RealtimeEstimatorOptions.ContinueOnError`). Evidence: `ResilienceOptionsTests`, `BridgeEndpointSettingTests`, `HealthProbeTests`, `AuditWiringTests`.

**Built as primitives, not yet applied (Partially achieved).** `ResilienceOptions` also carries a bounded reconnect backoff schedule (`BackoffDelay`), but no host drives it, so there is no supervised auto-reconnect loop. `DistrustedSources` (`GridSim.Core.Estimation`) marks a measurement source distrusted and forces its rows to pseudo-measurement treatment, but no product path applies it, and distrusted rows still count towards the chi-square redundancy. Evidence: `ResilienceOptionsTests`, `DistrustedSourceTests`.

**Deploying-party action.** Redundant instances behind the hosting layer need a shared distributed cache, because sign-on tickets are single-use per instance without one; edge rate limiting belongs at the reverse proxy.

## 5. What is already in code (not just planned)

- Data boundary: `ForwardInferenceGuard` (169 h), enforced at every dated ingester and re-asserted in the streaming engines.
- Restriction review gate: `RestrictionReview` - any `Dynamics/`->`Estimation/` fusion (DSE) is registered and asserted.
- Attack detection: `FdiaScreen` (physics and operational-envelope audit as a residual-cloaked-FDIA detector, pinned by `FdiaCloakedAttackTests`) + `HypothesisTestingBadData`.
- Forensic trail: the persisted, anchored audit trail (`AuditLogWriter`, `AuditAnchorFile`, `AuditRunRecorder`), with `EstimationAuditTrail` supplying the outcome text of an estimate.
- Web host: sign-in, single sign-on consumer, replay-only gate, session cap, key-ring encryption (DPAPI, or a certificate when configured).
- Determinism: estimates and replays are bit-identical run to run (`EstimatorDeterminismTests`, `GdaReplayDeterminismTests`), and no estimation code reads the clock (`EstimationClockIndependenceTests`), so a replay is exactly reproducible for an investigation.
- Access-control gate (primitive, not yet enforced by any host): `OperationRole`, `IdentityContext`, `RoleGuard.Require`, `AccessDeniedException` (`GridSim.Core.Security`), with an audited overload that writes a `SecurityEventKind.AccessDenied` entry on deny (`RoleGuardTests`).
- Per-security-event audit and signed anchor: `AuditRunRecorder.RecordSecurityEvent` / `SecurityAudit.Record` / `SecurityEventKind` / `SecuritySeverity`, at the detection sites of `estimate`, `serve`, `interpose` and the web resident estimator; `JsonLinesAuditSink` forwarding (`--audit-forward`, `Audit:ForwardPath`); `SignedAuditAnchor` (detached ECDSA P-256 over the anchor; `--audit-sign-key`, `--audit-verify-key`, `audit verify --pubkey`, `audit keygen`, `Audit:AnchorSigningKeyPath`, `Audit:AnchorVerificationKeyPath`); `SecurityEventMonitor` aggregates and escalates bursts (`SecurityAuditTests`, `SignedAuditAnchorTests`, `SecurityEventMonitorTests`, `AuditWiringTests`).
- Incident reporting: `IncidentReport` / `IIncidentSink` (`NullIncidentSink`, `BufferedIncidentSink`, `JsonLinesIncidentSink`) / `IncidentRouter` / `IncidentPolicy` / `SecurityIncidentSink` (`GridSim.Core.Diagnostics.Incident`), wired by `--incident-log` / `Audit:IncidentLogPath` (`IncidentRouterTests`, `AuditWiringTests`); `DistrustedSources` for containment, a primitive no product path applies yet (`DistrustedSourceTests`).
- Secrets: `ISecretStore` (`EnvironmentSecretStore`, `DirectorySecretStore`, `CompositeSecretStore`, `NullSecretStore`), BCL-only; web `Secrets:Directory` (`SecretStoreTests`, `DirectorySecretStoreTests`, `NoSecretInAuditTests`).
- Resilience and health: `ResilienceOptions` (`GridSim.Core.Net`), applied to every bridge client (its reconnect schedule not yet driven by any host); `ServiceLevelObjective` + `HealthProbe` (`GridSim.Core.Simulation.Health`), an SLO breach recorded as an `AvailabilityDegraded` security event at the end of a `serve` / resident run (`ResilienceOptionsTests`, `BridgeEndpointSettingTests`, `HealthProbeTests`, `AuditWiringTests`).
- Supply chain and attestation: `packages.lock.json`; SBOM hash injected into every shipped build and checked; signed build-provenance attestation of every Release file; `BuildProvenance`, `ComplianceManifest` and `ComplianceAttestation` (`GridSim.Core.Diagnostics.SupplyChain`) binding the control inventory to the build identity (`SupplyChainManifestTests`, `ComplianceAttestationTests`, `WorkflowReleaseGateTests`).
- PMU-anchored FDIA: `FdiaScreen.Screen` takes `protectedAnchors` and flags a feasible, in-limit cloaked attack through `FdiaScreenReport.AnchorInconsistent` (`FdiaProtectedAnchorTests`).
