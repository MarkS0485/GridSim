# Access control, supply chain and secrets - assurance notes

Companion to `caf-mapping.md` and `nis-oes-gap-assessment.md`, as at GridSim 2.1.010 (reviewed 2026-11-01; RC-1 released 2026-10-31 as 2.1.000), against NCSC CAF v4.0 (released 6 August 2025). These notes record, for access control, the software bill of materials, secrets and availability, what is in place today, with the type and test that evidences each, and the few remaining deploying-party actions. Statuses of record are in `caf-mapping.md` section 8. None of this weakens the load-bearing control: the `ForwardInferenceGuard` 169 h data boundary, which is enforced in code and needs no operator to be correct.

## 1. Access control

**In place.** The web host authenticates with a sign-in cookie and a single sign-on consumer (single-use, audience-checked tickets; it never acts as an authority). The production configuration runs replay-only (`GridSim:ReplayOnly`), which leaves the `/api` and `/ws/sim` endpoints unmapped, so a public instance has no solve surface to protect. Concurrent sessions are capped (`GridSim:MaxSessions`). A browser WebSocket upgrade to `/ws/sim` must come from the request's own host or an origin in `GridSim:AllowedOrigins` (otherwise 403). Since 2.1.008 the host answers only the names in `AllowedHosts` (default the loopback names), so a DNS-rebinding page gets a 400 before the socket is reached, and every answer carries `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options`, `X-Content-Type-Options` and `Referrer-Policy`, with HSTS on HTTPS outside Development (`caf-mapping.md` section 9, item 15, closed; `BugHunt1101WebTests`, `B170_*`, `B179_*`). `gridsim serve` binds no network port, and `GridBridgeClient` is an outbound client. Since 2.1.008 `pmu-ingest --live udp://:port` and `interpose` listen on 127.0.0.1 by default; a listener reachable from other machines needs a named sender or client, or an explicit opt-out flag (`B173_*`, `B174_*`).

**Enforced on the web host's solve surface (Partially achieved): role-based access-control gate.** The gate is built and tested (`GridSim.Core.Security`): `OperationRole` (`Viewer`, `Analyst`, `Operator`, `Administrator`), `IdentityContext` (principal id, role, correlation id from the cookie or SSO claims), `RoleGuard.Require(IdentityContext, OperationRole)` throwing `AccessDeniedException`, and an audited overload that writes a `SecurityEventKind.AccessDenied` audit entry for each deny. Since 2026-11-01 the web host calls it (`GridSim.Web.Site.AccessControl`) before `POST /api/solve` (Analyst), `GET /api/topology` (Viewer) and every `/ws/sim` control frame (Operator), taking the caller's band from its `GridSim.<role>` sign-in role claims or from `GridSim:AnonymousRole` (default Operator on an instance that answers only loopback names, Viewer otherwise), and writes each denial as one `AccessDenied` entry to its audit log when it has one. The manifest still records `rbac` as Partially achieved: the dashboard's own sessions are not role-gated, and a host without the resident estimator has no audit log, so its denials are refused but not audited. Evidence: `RoleGuardTests` (the primitive), `CafB2RoleGateWebTests` (the web host).

The least-privilege bands scope the service when the solve surface is exposed (the web host with replay-only off, or `RealtimeEstimatorHostedService`): a Viewer or Analyst subscribes to estimated-state frames and quality metrics (chi-square, covariance); an Operator additionally starts / stops / seeks the resident estimator and selects the bridge source (`presolved`, `estimated`, `live`, `solves`, `raw`); an Administrator additionally changes configuration (cadence, network model, feeds).

The gate is enforced in the hosting layer (with the identity the sign-in establishes and the host's audit writer), not in the Core library - Core stays a pure, side-effect-free estimator. The default keeps the documented single-user loopback use working (an anonymous caller on an instance that answers only loopback names holds Operator, which is why the existing tests still reach the solve surface without signing in) and is fail-safe elsewhere. The shipped exposure control in production is still the replay-only gate (`GridSim:ReplayOnly` leaves `/api` and `/ws/sim` unmapped). The horizon guard is independent of the gate: even an Administrator cannot make the estimator process data newer than the horizon, because the guard consults no role and has no bypass, and it caps what any caller can learn (week-stale reconstruction only) regardless of role.

## 2. Software Bill of Materials (SBOM)

**In place.** NuGet audit warnings are build errors on every build; CodeQL (`security-extended`) scans the C# when run by hand; Dependabot proposes grouped dependency updates monthly (Avalonia, SkiaSharp and HarfBuzzSharp updates together), merged by hand; `THIRD-PARTY-NOTICES.md` names every shipped package and bundled font with its licence (`ThirdPartyNoticesTests` checks it against every package in the lock files). The RC-1 GitHub Release carries one CycloneDX SBOM, for the command line tool (`gridsim-2.1.000.sbom.json`, its SHA-256 stamped into the CLI), `SHA256SUMS.txt`, and signatures on the three Windows executables and the NuGet package from a self-signed certificate checked by its thumbprint; the Linux files are not signed. The desktop apps and the NuGet package have no SBOM of their own.

**Written into the release workflow, not exercised.** `release.yml` is written to build five CycloneDX SBOMs from the .NET restore graph, all Release files (the CLI, the web host, GridSim.Core for the NuGet package, and the Avalonia and WPF desktop apps), plus an SBOM of the built web image made with Syft (the Ubuntu base's packages and the ASP.NET runtime; GR-439), with the bundled .NET runtime listed in the self-contained apps' SBOMs, build each shipped artefact with the SHA-256 of its own SBOM injected (the NuGet package with the GridSim.Core SBOM's hash), fail on a known-vulnerable direct or transitive package, rebuild the Linux CLI byte for byte as a gate on the release, put a signed build-provenance attestation on every Release file and the web image (`gh attestation verify <file> -R <owner>/GridSim`), and sign the Windows CLI, the Windows WPF and Avalonia executables and the NuGet package when the signing secret is set (it is not). Since 2026-11-01 (GA-5, an owner decision) its ship scope includes the desktop apps as RC-1 shipped them (WPF for win-x64, Avalonia for win-x64 and linux-x64; no macOS desktop build, no smoke run since they need a display). At RC-1 the workflow refused the RC tag form, so it did not build RC-1, which was built, signed and published by hand from the owner's build machine; no RC-1 file carries a provenance attestation (`caf-mapping.md` section 4.4). Since 2.1.008 it accepts a release-candidate tag (marked a pre-release; no NuGet package or image pushed for a candidate), but no release has been made through it, so none of the above has run.

- The dependency surface is deliberately small: the Core estimator has **no third-party runtime dependencies** beyond the .NET base class library (linear algebra, XML, crypto are all BCL); the CLI adds Parquet.Net and ILGPU; the web host adds ASP.NET Core; the Avalonia desktop app adds Avalonia, SkiaSharp, HarfBuzzSharp (with native libraries) and CommunityToolkit.Mvvm; tests add xUnit. A small surface is itself an assurance property.
- Review transitive additions when a lock file changes (work lands directly on `main`; there are no pull requests).

**In place.** Per-project `packages.lock.json` lock files (`RestorePackagesWithLockFile=true` in `Directory.Build.props`) record the restore graph. Since 2.1.008 `global.json` pins the SDK to 10.0.401 with no roll-forward, every workflow and the container image use exactly that SDK, and restores on GitHub Actions and in the image build run in locked mode, so there a restore that would change a lock file fails (a restore on the owner's machine is not locked; `BugHunt1101WebTests`, `B161_*`). `BuildProvenance` (`GridSim.Core.Diagnostics.SupplyChain`) exposes version, commit, toolchain (the .NET SDK stamped at build time), SBOM hash, source-tree state and build hash at runtime. Since 2.1.008 a build reports `release build  yes` only when the injected SBOM hash (`-p:GridSimSbomSha256=<hash>`) is exactly 64 hexadecimal digits, the commit is known and the source tree was clean at build time; otherwise it reports `release build  no` with the reason (`B176_*`). The check proves form and a clean tree, not that the workflow built the binary. For RC-1 the owner injected the CLI SBOM's hash in the local build and checked both CLI builds after signing (`RC1.md`). The build hash is an identity label over those metadata strings, not an integrity proof (it covers no artefact bytes); download integrity comes from Authenticode, the NuGet signature and `SHA256SUMS.txt`. `ComplianceManifest` (a hand-maintained inventory) + `ComplianceAttestation` bind the control inventory to the build identity: the verdict is COMPLIANT only for a release build with every in-scope control recorded Achieved; a build that is not a release build reports `NOT ATTESTED` and `gridsim compliance verify` exits 1. At this release `rbac`, `distrusted-source`, `resilience` and, since 2.1.008, `supply-chain` and `secure-sdlc-attestation` are recorded Partially achieved (13 of 18 in-scope controls Achieved), so a release build reads `NOT COMPLIANT` (the A4.b secure-SDLC attestation). Evidence: `SupplyChainManifestTests`, `ComplianceAttestationTests`, `WorkflowReleaseGateTests`, `BugHunt1101WebTests` (`B196_*`).

**Open (owner).** Build the next release through the release workflow (it accepts the RC tag form since 2.1.008; its ship scope includes the desktop apps and five SBOMs since 2026-11-01, written and not yet run; the signing secrets are still to settle); confirm that release publishes an SBOM for each shipped application; have a green CI run before a release is published. CI runs by hand, not on every push, a risk-accepted deviation (see `caf-mapping.md` section 4.4 and section 9, items 10 to 13).

## 3. Secrets management

The estimator itself holds **no secrets** in its core path - it consumes files and streams of measurements and emits states. Secrets appear only at the edges:

- Feed credentials (a PMU / PDC endpoint, a lake path, a message bus) and the licence key - supplied through environment variables or configuration, never committed.
- The web host's data-protection key ring - encrypted at rest with DPAPI on Windows by default, and with a PKCS#12 certificate elsewhere when `Auth:KeyCertificatePath` is set (without one, Linux stores the keys unencrypted and warns at start-up); a protection setting that cannot be honoured stops start-up.
- Release signing material - held by the owner off the repository (the RC-1 signatures were made on the owner's build machine); the repository holds only the public certificate, and the repository secrets the release workflow is written to read are not set.
- Any operator API auth material - handled by the hosting layer's sign-in.

**In place.** `ISecretStore` (`GridSim.Core.Security`), with `EnvironmentSecretStore`, `DirectorySecretStore`, `CompositeSecretStore` and `NullSecretStore`, is BCL-only (no new third-party dependency); services resolve secrets (for example the key-ring certificate password, through `KeyRingProtection`) through it rather than from plain configuration. `DirectorySecretStore` reads one file per secret (Docker / Compose secrets at `/run/secrets`, a Kubernetes secret volume, systemd `$CREDENTIALS_DIRECTORY`); the web setting `Secrets:Directory` puts it in front of the environment, so the key-ring certificate password need not be in configuration or the environment. No OS-keychain or vault backend ships; a deployer can supply their own `ISecretStore` in code. The licence key is signed, not encrypted (it is inspectable, not a confidential secret), so it needs no store. Evidence: `SecretStoreTests`, `DirectorySecretStoreTests`, `NoSecretInAuditTests`.

Rule: no secret in source, no secret in the audit log (the audit trail records provenance, timestamps, input hashes and verdicts - never credentials), no secret in an exported state. A test enforces the audit rule: `NoSecretInAuditTests`.

## 4. Availability and minimising impact (CAF B5, D1)

**In place.** The resident estimator continues past a failed window by default (`ContinueOnError`) and reports processed / converged / rejected / failed counts; `GridBridgeClient` times out a query after 60 s and fails every pending query when the stream faults; the web host caps sessions; the container health check probes the web host. The chi-square gate and the `FdiaScreen` are the "detect a bad or attacked state before acting on it" controls; the audit trail is the forensic record; the deterministic replay path (`GdaReplayLoop`, and `RealtimeEstimatorEngine` on a recorded window stream) re-derives a past state bit for bit for post-event forensics.

**In place.** `ResilienceOptions` (`GridSim.Core.Net`) carries the resource limits (bridge message cap, in-flight-query cap) and the transport policy, and the web and desktop hosts apply it to every bridge client they create; `GridBridgeClient` refuses an unencrypted `ws://` endpoint unless explicitly allowed (web `GridSim:BridgeAllowUnencrypted=true`, desktop `BridgeAllowUnencrypted`; without it a `ws://` endpoint stops web start-up). `ServiceLevelObjective` + `HealthProbe` (`GridSim.Core.Simulation.Health`) fold the engine's `RealtimeRunSummary` into a `HealthReport`; at the end of a `gridsim serve` run with `--audit-log`, or of the web resident estimator's run with `Audit:LogPath`, an SLO breach is recorded as an `AvailabilityDegraded` security event, which becomes an incident when `--incident-log` / `Audit:IncidentLogPath` is set (the `/health` endpoint itself raises nothing; it answers 503). There is no degraded-mode fallback to a last-good estimate: a failing window is skipped and counted and the resident loop carries on (`RealtimeEstimatorOptions.ContinueOnError`). Evidence: `ResilienceOptionsTests`, `BridgeEndpointSettingTests`, `HealthProbeTests`, `AuditWiringTests`.

**Applied, off by default (Partially achieved).** `ResilienceOptions` also carries a bounded reconnect backoff schedule (`BackoffDelay`). Since 2026-11-01 `BridgeReconnectSupervisor` (`GridSim.Core.Net`) drives it: on a lost bridge stream it waits `BackoffDelay(n)` and reconnects through the host's own connect path, up to `MaxReconnectAttempts` (0 means no bound), then reports one give-up; a horizon rejection (`ForwardInferenceException`) is never retried and a success resets the count. The web host applies it with `GridSim:BridgeReconnect=true` and `GridSim:BridgeReconnectMaxAttempts`, the desktop app with `BridgeAutoReconnect` and `BridgeReconnectMaxAttempts`; both are off by default, the legacy WPF window is not wired, the bridge client has no keep-alive, and each attempt and the give-up go to the host's log, not the security audit. A release test run has not yet confirmed it (`BridgeReconnectSupervisorTests`, `BridgeReconnectHostWiringTests`). `DistrustedSources` (`GridSim.Core.Estimation`) marks a measurement source distrusted and forces its rows to pseudo-measurement treatment; since 2026-11-01 `estimate --distrust`, `serve --distrust` and `Realtime:DistrustedSources` apply it, write one `DistrustedSource` security event per source per run and leave the distrusted rows out of the chi-square J and degrees of freedom (held Partially achieved until the release test run). Evidence: `ResilienceOptionsTests`, `DistrustedSourceTests`, `DistrustedSourceRedundancyTests`, `DistrustedSourceSettingTests`.

**Deploying-party action.** Redundant instances behind the hosting layer need a shared distributed cache, because sign-on tickets are single-use per instance without one; edge rate limiting belongs at the reverse proxy.

## 5. What is already in code (not just planned)

- Data boundary: `ForwardInferenceGuard` (169 h), enforced at every dated ingester and re-asserted in the streaming engines.
- Restriction review gate: `RestrictionReview` - any `Dynamics/`->`Estimation/` fusion (DSE) is registered and asserted.
- Attack detection: `FdiaScreen` (physics and operational-envelope audit as a residual-cloaked-FDIA detector, pinned by `FdiaCloakedAttackTests`) + `HypothesisTestingBadData`.
- Forensic trail: the persisted, anchored audit trail (`AuditLogWriter`, `AuditAnchorFile`, `AuditRunRecorder`), with `EstimationAuditTrail` supplying the outcome text of an estimate.
- Web host: sign-in, single sign-on consumer, replay-only gate, session cap, key-ring encryption (DPAPI, or a certificate when configured).
- Determinism: estimates and replays are bit-identical run to run (`EstimatorDeterminismTests`, `GdaReplayDeterminismTests`), and no estimation code reads the clock (`EstimationClockIndependenceTests`), so a replay is exactly reproducible for an investigation.
- Access-control gate: `OperationRole`, `IdentityContext`, `RoleGuard.Require`, `AccessDeniedException` (`GridSim.Core.Security`), with an audited overload that writes a `SecurityEventKind.AccessDenied` entry on deny (`RoleGuardTests`); enforced by the web host on `POST /api/solve`, `GET /api/topology` and every `/ws/sim` control frame (`GridSim.Web.Site.AccessControl`, `CafB2RoleGateWebTests`).
- Per-security-event audit and signed anchor: `AuditRunRecorder.RecordSecurityEvent` / `SecurityAudit.Record` / `SecurityEventKind` / `SecuritySeverity`, at the detection sites of `estimate`, `serve`, `interpose` and the web resident estimator; `JsonLinesAuditSink` forwarding (`--audit-forward`, `Audit:ForwardPath`); `SignedAuditAnchor` (detached ECDSA P-256 over the anchor; `--audit-sign-key`, `--audit-verify-key`, `audit verify --pubkey`, `audit keygen`, `Audit:AnchorSigningKeyPath`, `Audit:AnchorVerificationKeyPath`); `SecurityEventMonitor` aggregates and escalates bursts (`SecurityAuditTests`, `SignedAuditAnchorTests`, `SecurityEventMonitorTests`, `AuditWiringTests`).
- Incident reporting: `IncidentReport` / `IIncidentSink` (`NullIncidentSink`, `BufferedIncidentSink`, `JsonLinesIncidentSink`) / `IncidentRouter` / `IncidentPolicy` / `SecurityIncidentSink` (`GridSim.Core.Diagnostics.Incident`), wired by `--incident-log` / `Audit:IncidentLogPath` (`IncidentRouterTests`, `AuditWiringTests`); `DistrustedSources` for containment, a primitive no product path applies yet (`DistrustedSourceTests`).
- Secrets: `ISecretStore` (`EnvironmentSecretStore`, `DirectorySecretStore`, `CompositeSecretStore`, `NullSecretStore`), BCL-only; web `Secrets:Directory` (`SecretStoreTests`, `DirectorySecretStoreTests`, `NoSecretInAuditTests`).
- Resilience and health: `ResilienceOptions` (`GridSim.Core.Net`), applied to every bridge client (its reconnect schedule driven by `BridgeReconnectSupervisor` in the web host and the desktop app, off by default); `ServiceLevelObjective` + `HealthProbe` (`GridSim.Core.Simulation.Health`), an SLO breach recorded as an `AvailabilityDegraded` security event at the end of a `serve` / resident run (`ResilienceOptionsTests`, `BridgeEndpointSettingTests`, `HealthProbeTests`, `AuditWiringTests`).
- Supply chain and attestation: `packages.lock.json` (locked-mode restore on CI and in the image build, SDK pinned by `global.json`); `BuildProvenance` (release build needs a 64-hex SBOM hash, a known commit and a clean tree), `ComplianceManifest` and `ComplianceAttestation` (`GridSim.Core.Diagnostics.SupplyChain`) binding the control inventory to the build identity; in the release workflow (not exercised for RC-1), SBOM hash injection into every shipped build and a signed build-provenance attestation of every Release file (`SupplyChainManifestTests`, `ComplianceAttestationTests`, `WorkflowReleaseGateTests`).
- PMU-anchored FDIA: `FdiaScreen.Screen` takes `protectedAnchors` and flags a feasible, in-limit cloaked attack through `FdiaScreenReport.AnchorInconsistent` (`FdiaProtectedAnchorTests`); the significance margin uses the tightest meter for bus quantities and single-line branch flows (`BugHunt1101WebTests`, `B189_*`).
- Web host exposure: `AllowedHosts` host list and security headers with HSTS (`Site.HostAllowList`, `Site.SecurityHeaders`; `B170_*`, `B179_*`).
